- G-02 показал `OK … 0 B` на странице со скриптом в 6,5 KB, а список шрифтов, собранный наполовину, мерился бы за целый -> разбор HTML и JS регуляркой по белому списку (`[^>]*`, `[\w$\s{},*]`) и глоб по семейству: всё, что не узнано, выпадает из счёта молча, а не валит гейт -> гейт разбирает по грамматике конструкции, а не по тому, что обычно выдаёт сборщик, у каждого разбора есть юнит-тест с краевыми формами (`tests/unit/size-gate.test.ts`), а предмет бюджета перечисляется явно и сверяется целиком
- После первой правки G-02 всё ещё терял скрипт за `<meta content="Кодирует тег <script>">` и валил правильную сборку на `x==="export"` -> регулярка искала `<script` и `import` по сырому тексту, не зная, где в HTML значение атрибута, а в JS — строка; первая правка закрыла найденные формы, а не класс -> разбор держит контекст токенизатора (чужой тег поглощается целиком, у ключевого слова проверяются сосед слева и то, что грамматика допускает справа), а разбор гоняется на враждебном вводе с замером времени
- G-02 висел минутами на файле с пятью строками обычного комментария `// … import …` -> альтернатива внутри повторяемой группы совпадала с одним текстом несколькими способами (`\/\/[^\r\n]*` кончался посреди строки и отдавал остаток имени и пробелу), и число разборов перемножалось с каждой строкой; тест на скорость гонял ввод без комментариев -> каждая альтернатива под `*` совпадает с текстом одним способом (разные первые символы, жёсткий конец), а тест на скорость содержит каждую альтернативу группы — комментарии, строки, имена
- G-02 молча потерял `import './polyfill.js'` без `;` после комментария со словом `import` и валил сборку на закомментированном импорте в классическом скрипте -> клауза брала имена по символу и перешагивала следующее объявление, проглатывая его спецификатор как строковое имя, а импорты искались и там, где их не бывает, — в классическом скрипте -> токен разбора — целое слово, и ключевые слова, начинающие новое объявление, в клаузу не входят; разбор применяется только к тому, что исполняется как модуль; разборщик сверяется с настоящим лексером (`es-module-lexer`) на `node_modules`, а не только на своих примерах
- G-02 ложно валил правильную сборку на `// import { debug } from './debug.js'`, на `@example` в JSDoc и на примере кода в шаблонной строке, а каждая правка регулярки открывала новый класс ошибок — пять прогонов /check подряд -> JS разбирался регуляркой, которая не знает, где в нём комментарий, строка или регулярное выражение -> язык с контекстом разбирается лексером своего инструментария (`es-module-lexer`, лексер Vite, D-158), регулярка — только для фиксированной грамматики; после второго класса ошибок в самописном разборщике ставится вопрос о настоящем парсере, а не третья заплатка
- G-02 показал `OK 73 B` на модуле, который браузер грузит на 2039 B, — файл сохранён как UTF-8 с BOM, и первый импорт пропал -> `readFile(…, 'utf8')` оставляет U+FEFF, а лексер читает `BOM + import` как имя; браузер BOM снимает при декодировании -> гейт читает файл так же, как его декодирует потребитель (браузер): ведущий BOM снимается до разбора, а тесты разборщика включают кодировочные края — BOM, CRLF, разделители строк
