# SCR-05 · JWT Inspector

**Реестр:** [screen-map.md](../screen-map.md) §2 · **Тип:** наполнение [SCR-03](scr-03-tool-route.md) ·
**Роль:** ROLE-01, персона П-1 · **Сущности:** ENT-14, ENT-15, ENT-23
**Сценарии:** FL-05 целиком · FL-09 шаги 2 и 4
**Истории:** US-021, US-022, US-038, US-041, US-042
**Решено:** три состояния подписи, `alg: none` — предупреждение, RS256/ES256 — следующий релиз (D-68); перечень teardown и гейт-инвариант (D-48); предупреждение несёт янтарную подложку, распознавание — акцентную (D-78)

> Форма — SCR-03. Здесь описано **только отличие**. Самая дорогая точка доверия во всём продукте:
> на шаге разворачивания поля ключа человек решает, вставлять ли боевой секрет в браузерную
> страницу, и всё, что работает в этот момент, — предупреждение рядом с полем и ссылка на процедуру.

---

## 1. Зоны макета — отличие от SCR-03

| Зона | Что меняется |
|---|---|
| D область результата | Разбита на именованные разделы стандарта: `header`, `payload`, `signature`. Подписи — как в стандарте, без перевода и без кавычек |
| D, блок claim-ов | Список пар «claim — значение», моноширинно. Временные claim-ы (`exp`, `iat`, `nbf`) показываются в двух строках: UTC и локальная со смещением, рядом — исходное число без изменений |
| D, метка срока | `Истёк` — акцентная подложка с чернильной чертой рядом со значением `exp` |
| D, у каждого значения | Действие `Продолжить с этим` — когда claim содержит Base64 или вложенный JSON |
| **E′ · поле ключа подписи** | **Свёрнуто по умолчанию**, стоит ниже разделов результата, отдельным блоком за линией `--border-subtle` |
| E′, развёрнутое | Поле ввода ключа + переключатель `Показать` / `Скрыть` + кнопка `Проверить подпись` + подсказка + ссылка на «Как это проверить» |
| E′, исход | Одна строка: `Подпись верна` (`--text-success`) либо `Подпись не совпала` (`--text-danger`), рядом всегда слово и данные, которые её вызвали |

**Поле ключа — единственное место продукта с этими правилами вёрстки:**

- значение **визуально маскировано**, но это **не** `type="password"` — иначе менеджер паролей
  предложит сохранить чужой секрет для нашего домена (D-25 п. 4);
- `autocomplete="off"`, `spellcheck="false"`;
- цвет `--text-success` `#0F6B45` расходуется здесь и только здесь: он не разменивается на «скопировано»
  и «готово», иначе обесценится там, где единственный отвечает за утверждение (design-plan §5.1);
- при уходе с маршрута поле **видимо обнуляется** — teardown является визуальным требованием,
  потому что экран часто демонстрируется в звонке (design-plan §2).

**Конфликт акцентная подложкаа на этом экране назван заранее.** Одна и та же жёлтая подложка обозначает и
распознанный определителем тип, и предупреждение `Истёк`. В JWT Inspector они встречаются
одновременно чаще, чем где-либо ещё — **D-78**; при подтверждении смешения предупреждение получает
штриховую черту вместо сплошной, а не второй цвет.

## 2. Приоритет элементов

1. **`exp` и `aud` в payload.** Ради них приходит подавляющее большинство, и на них сценарий
   завершается: верификация сделана необязательным шагом сознательно (D-25 п. 1).
2. **Метка `Истёк`.** Ответ на вопрос, с которым пришли из ошибки 401.
3. **Разделы `header` / `payload`.** Структура важнее оформления: подписи набраны, а не нарисованы.
4. **Свёрнутое поле ключа.** Видно, что оно есть, но оно не зовёт: свёрнутость и есть сообщение
   «это необязательно».
5. **Предупреждение рядом с полем ключа.** Одно предложение, без запугивания. Работает в
   единственный момент, когда лендинг и счётчик уже не читаются.
6. **Исход проверки.** Появляется на месте, без тоста и без модалки.

## 3. Поведение на мобильном

- **Claim-ы становятся вертикальными парами** «имя над значением», а не таблицей в две колонки:
  claim-имена короткие, значения длинные, и таблица на 360 px ломает именно значения.
- **Длинное значение claim переносится по символам** внутри своей ячейки; горизонтальной прокрутки
  у страницы не появляется.
- **Поле ключа остаётся свёрнутым** и на мобильном; развёрнутое поле поднимает клавиатуру, поэтому
  кнопка `Проверить подпись` обязана оставаться видимой над ней.
- **`Показать` / `Скрыть`** — цель не менее 32 px: это действие с секретом на экране, промах по нему
  дороже обычного.
- **Демонстрация экрана** — реальный контекст и на мобильном тоже (звонок с телефона): маскирование
  и видимое обнуление при уходе работают одинаково.

## 4. Тексты

| Место | Строка |
|---|---|
| H1 | `JWT Inspector` |
| Вводный абзац | `Разбор header и payload, срок действия по exp, локальная проверка подписи HS256. Токен не покидает вкладку — внешних запросов на этой странице 0.` |
| Подсказка поля | `Вставьте токен — результат появится ниже` |
| Подписи разделов | `header` · `payload` · `signature` · `exp` · `iat` · `nbf` · `claim` |
| Подсказка у поля ключа | `Ключ нужен только для проверки подписи` |
| Кнопки | `Проверить подпись` · `Показать` / `Скрыть` · `Развернуть` / `Свернуть` |
| Исход, сошлась | `Подпись верна` |
| Исход, не сошлась | `Подпись не совпала. Проверьте ключ подписи и алгоритм` |
| Не три сегмента | `Ожидались три сегмента, разделённые точкой. Найдено два` |
| `alg` не HS256 | `Подпись RS256 локально не проверяется — нужен открытый ключ. header и payload разобраны ниже` |
| Дата claim | `1 января 2026, 03:00 UTC` · `1 января 2026, 06:00 (UTC+3)` · исходное `1735689600` |
| Истёкший | `Истёк · 1 января 2026, 03:00 UTC · 4 часа назад` |

**Запрещено здесь.** `Токен валиден` — валидна подпись, а про токен это ничего не говорит ·
`Просрочен`, `Невалиден` вместо `Истёк` · `Секрет`, `Пароль`, `Секретная фраза` вместо `Ключ` ·
`полезная нагрузка`, `заголовок` вместо `payload` и `header` · `Расшифровать` — base64 не шифр, и
путать это в продукте про секреты нельзя · `ваш токен могут украсть`, `не рискуйте` (CG-07:
страх в интерфейсе про секреты читается как манипуляция) · цитата токена или ключа в тексте
ошибки (CG-18, REQ-TRUST-06).

## 5. Состояния

- **Loading.** Не бывает: разбор укладывается в кадр на реальных токенах.
- **Empty.** `Пример` разобранного токена (синтетического — боевых значений в продукте нет нигде,
  включая примеры). Поле ключа свёрнуто и здесь. **Отсутствие `exp` пустым состоянием не является:**
  срок действия не показывается, сообщения об ошибке нет — это допустимый токен.
- **Error.** Обрезанный при копировании из лога токен — самый частый реальный случай: ошибка с
  позицией за ≤ 300 мс, поле не очищается. Три сегмента есть, но `header` не разбирается в JSON с
  `alg` — кандидат JWT уступает следующей ступени лестницы, чипс `JWT` остаётся доступен вручную.
- **Уход с маршрута.** Поле ключа, токен и производные значения обнуляются. Возврат даёт пустые
  поля — контракт, а не сбой. Очистка по потере фокуса вкладки **не** делается: человек ушёл
  скопировать секрет и не должен вернуться к пустому полю. Состав «производных значений» — D-48.
