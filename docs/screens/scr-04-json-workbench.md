# SCR-04 · JSON Workbench

**Реестр:** [screen-map.md](../screen-map.md) §2 · **Тип:** наполнение [SCR-03](scr-03-tool-route.md) ·
**Роль:** ROLE-01, персона П-2 · **Сущности:** ENT-12, ENT-13
**Сценарии:** FL-06 целиком · FL-02 · FL-11
**Истории:** US-019, US-020, US-030, US-032, US-064
**Решено:** поиск идёт по ключам и значениям сразу (D-72); глубина вложенности — отдельная ось порога `jsonDepth` (D-73); подсветка — палитра `--code-*` кита (D-53); числа порогов замером на В-2, до него `provisional` (D-51); кнопка называется `Проверить JSON` (D-60)

> Форма — SCR-03. Здесь описано **только отличие**. Главный инструмент каталога: на нём калибруется
> оценка трудоёмкости (M-03) и на нём же дороже всего ошибка (D-53).

## 1. Зоны макета — отличие от SCR-03

| Зона | Что меняется |
|---|---|
| C поле ввода | SSG-textarea на первом кадре; после первой отрисовки её подменяет редактор CodeMirror, **не двигая каретку**. Чанк не приехал — сценарий проходится на textarea целиком |
| D область результата | Вместо плоского значения — **виртуализованное дерево**: в DOM живут только видимые узлы, число узлов DOM не растёт с размером документа |
| D, панель над деревом | Строка операций: `Форматировать`, `Минифицировать`, сортировка ключей, `Проверить JSON` — `--type-ui`, контурные кнопки, ни одной цветной |
| D, строка поиска по дереву | Отдельное поле над деревом, действие `Найти` — то же слово, что в палитре |
| D, узел дерева | Ключ (вес 600), значение (400), пунктуация `--code-punct`. Развернуть/свернуть, `Скопировать путь`, `Продолжить с этим` на значении |

**Подсветка трёхролевая и без цветов типов.** Строки, числа, `null` и `boolean` одним цветом
чернил: человек открыл форматтер, чтобы найти поле, а не читать код, а типы видны по кавычкам и
литералам. Решение спорное и проверяется на корпусе фикстур — **D-53**; при провале в палитру
возвращается ровно один дополнительный оттенок чернил, а не пять цветов.

**Кодовая панель не темнеет в светлой теме.** Машинность вывода уже обеспечена шрифтом, вторая
тёмная поверхность создала бы третью тему на экране.

**Совпадение поиска — акцентная подложка `--surface-accent-soft` с чернильной чертой.** Тот же приём, что у определителя.
При многих совпадениях правило «одно акцентная подложканое пятно на экран» уступает: подсвечиваются все
видимые совпадения, потому что здесь акцентная подложка и есть результат операции, а не метка о ней.

## 2. Приоритет элементов

1. **Дерево.** Ради него открывают инструмент; оно занимает столько высоты, сколько есть.
2. **Поиск по дереву.** Второй по важности элемент: если поиск ищет не то, человек не переспрашивает
   — он возвращается к прокрутке глазами, и весь выигрыш исчезает (FL-06, «где отваливаются»).
3. **`Скопировать путь` на узле.** Точка успеха сценария FL-06.
4. **Строка операций.** Форматирование применяется само при разборе; кнопки нужны для второго и
   третьего действия, а не для первого.
5. **Поле ввода.** После получения дерева уходит на второй план, но не сворачивается: правка на
   месте — весь смысл того, что ошибка не очищает ввод.

## 3. Поведение на мобильном

- **Дерево остаётся деревом**, а не превращается в список: отступ уровня 12 px вместо 16, узел
  переносится по словам. Горизонтальной прокрутки у страницы нет; горизонтально прокручивается
  только длинное значение внутри своего узла.
- **Строка операций** сворачивается в две строки кнопок, а не в меню «ещё»: скрытое действие на
  мобильном равно отсутствующему.
- **`Скопировать путь`** — самое частое действие на узле, поэтому остаётся видимым, а не появляется
  по ховеру: ховера на тач-устройствах нет, и он не имеет права быть единственным носителем смысла
  (design-plan §6).
- **Редактор CodeMirror на мобильном не подменяет textarea.** Чанк весит до 90 KB gzip, а
  клавиатурных преимуществ на мобильном не даёт; это решение экрана, а не требования — отмечено
  здесь явно.
- Виртуализация обязательна тем более: 100 000 узлов на мобильном ломают отрисовку раньше, чем
  парсинг (D-30).

## 4. Тексты

| Место | Строка |
|---|---|
| H1 | `JSON Workbench` |
| Подсказка поля | `Вставьте JSON — результат появится ниже` |
| Кнопки | `Форматировать` · `Минифицировать` · `Проверить JSON` · `Найти` · `Развернуть` / `Свернуть` · `Скопировать путь` |
| Ошибка разбора | `Ожидалась запятая. Строка 12, позиция 34` |
| Незакрытая структура | `Структура не закрыта: не хватает }. Строка 118, позиция 1` |
| Мягкий порог | `Ввод больше ‹2 МБ›. Дальше будет медленно: всё считается у вас в браузере` + `Форматировать всё равно` |
| Поиск без совпадений | `Ничего не нашлось` |

**Запрещено здесь.** `Скопировать ключ` — слово «ключ» занято ENT-15, подпись только
`Скопировать путь` · `Beautify`, `Prettify`, `Причесать`, `Отформатировать` вместо `Форматировать` ·
`Сжать` вместо `Минифицировать` — сжатие это gzip и другой бюджет · `Валидировать` вместо
`Проверить JSON` · `JSON форматтер` в заголовке — имя инструмента не переводится (CG-12).

## 5. Состояния

- **Loading.** Разбор и форматирование в Web Worker; главный поток не блокируется дольше 50 мс
  подряд. Первый кадр — textarea. При документе за мягким порогом — предупреждение до операции,
  прогресс и `Отменить` во время.
- **Empty — два обязательных.** До первого ввода: `Пример` разобранного ответа API плюс подсказка
  поля. Поиск без совпадений: `Ничего не нашлось`, **дерево остаётся на месте и свёрнутость узлов
  не меняется**; очистка строки поиска возвращает дерево в состояние до поиска.
- **Error.** Сообщение с позицией за ≤ 300 мс, поле ввода не очищается и правится на месте, акцентная подложка
  на позиции ошибки в самом вводе. Это ровно тот случай, ради которого запрещено очищать поле.
