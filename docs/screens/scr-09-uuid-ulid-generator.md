# SCR-09 · UUID/ULID Generator

**Реестр:** [screen-map.md](../screen-map.md) §2 · **Тип:** наполнение [SCR-03](scr-03-tool-route.md) ·
**Роль:** ROLE-01 · **Сущности:** ENT-13
**Сценарии:** FL-12 целиком
**Истории:** US-027, US-028, US-066
**Решено:** значение показывается сразу, пустого состояния нет (D-81); размер пакета — ось порога `batchSize` (D-73); при недоступном `crypto.getRandomValues` значения не выдаются вовсе (D-64); автозначение событий не порождает (D-52)

> Форма — SCR-03. Единственный инструмент каталога, **которому ввод не нужен**. Поле ввода при этом
> остаётся и служит разбору чужого значения: форма не меняется от того, что у инструмента другая
> механика (REQ-TOOL-07, US-029 критерий 3).

---

## 1. Зоны макета — отличие от SCR-03

| Зона | Что меняется |
|---|---|
| C поле ввода | Остаётся на месте и служит **разбору** существующего значения, а не генерации. Подсказка поля говорит именно об этом |
| C′ · управление генерацией | Над областью результата: чипсы версии `v4` / `v7` / `ULID`, поле количества, кнопка `Сгенерировать` |
| D, режим генерации | Список значений по одному на строку, моноширинно, `Скопировать` на строке и `Скопировать` на весь пакет |
| D, режим разбора | Пары «свойство — значение»: корректность, версия, вариант; для ULID — временная метка |

**Поле количества — единственное числовое поле продукта.** Ширина по содержимому (4 знака),
`tabular-nums`, стрелок-спиннера нет: спиннер добавляет две цели нажатия ради значения, которое
набирается быстрее. Правило валидации поля не описано ни одним требованием — **D-73**.

**Порядок C′ и D важен.** Управление стоит **над** результатом, потому что человек, пришедший за
вторым пакетом, идёт к нему сверху вниз; результат, стоящий выше своего управления, заставляет
возвращаться взглядом.

---

## 2. Приоритет элементов

1. **Первое значение в области результата.** Оно и есть ответ; в подавляющем большинстве визитов
   человек копирует его и уходит.
2. **`Скопировать`.** Точка успеха сценария. При пакете — копирование всего пакета важнее
   копирования строки.
3. **Чипсы версии.** Выбор `v4` против `v7` — единственное осмысленное решение на экране.
4. **Поле количества.** Нужно меньшинству; стоит рядом с кнопкой, а не отдельным блоком.
5. **Поле ввода для разбора.** Второй сценарий инструмента, и он тише первого: подсказка объясняет,
   что поле здесь не для генерации.

---

## 3. Поведение на мобильном

- **Пакет значений** остаётся списком строк; длинный UUID переносится по символам внутри своей
  строки, а не прокручивается горизонтально.
- **`Скопировать` на строке** — цель не менее 32 px и видима без ховера.
- **Поле количества и `Сгенерировать`** стоят в одну строку и на мобильном: два элемента шириной
  4 знака и 20 знаков помещаются в любую ширину.
- **Системная клавиатура для поля количества** — числовая (`inputmode="numeric"`): это единственное
  место продукта, где тип клавиатуры имеет значение.
- Автофокус на мобильном уходит **не** в поле ввода: генератору ввод не нужен, и поднимать
  клавиатуру ради поля, которым воспользуется меньшинство, — прямая потеря первого экрана.
  Это отличие от SCR-03 и оно намеренное.

## 4. Тексты

| Место | Строка |
|---|---|
| H1 | `UUID/ULID Generator` |
| Чипсы версии | `v4` · `v7` · `ULID` |
| Кнопка | `Сгенерировать` |
| Кнопка результата | `Скопировать` → `Скопировано` на 1,2 с |
| Подсказка поля ввода | Поле служит разбору существующего значения — строка не написана, см. ниже |
| Дефектное значение | Сообщение с указанием места; поле не очищается (NFR-15) |

**Запрещено здесь.** `Создать` вместо `Сгенерировать` — создание относится к сущностям, а их
пользователь не создаёт (глоссарий §3) · `Скачать` · `Ошибка`, `Упс`.

### Противоречие, которое нельзя обойти вёрсткой

- **FL-12 шаг 1 и US-066 критерий 1:** значение сгенерировано и показано **без действия человека**,
  на первом кадре. Тогда пустого состояния у области результата не существует вовсе.
- **content-guide §5:** для генератора до генерации стоит строка
  `Нажмите «Сгенерировать» — значения появятся здесь`. Тогда пустое состояние есть, а критерий
  US-066 не выполняется.

Одновременно верным быть не может. **Решено D-81 в пользу первого:** значение показано на первом
кадре, пустого состояния у генератора нет, строка гайда удалена. Опасение про PM-01 снято раньше,
решением D-52: автозначение событий не порождает, поэтому метрика не завышается.

## 5. Состояния

- **Loading.** Не бывает при разумном пакете. Размер пакета — собственная ось порога `batchSize`
  (D-73): REQ-LIMIT-03 описывает и её, а не только размер ввода.
- **Empty.** У области результата пустого состояния нет: значение показано на первом кадре
  (D-81). Пустое состояние поля ввода отдельного текста не требует: поле служит разбору, а не
  генерации.
- **Error.** Недоступен `crypto.getRandomValues` — значения из небезопасного источника **не
  выдаются**: инструмент, выдающий идентификаторы из небезопасного источника, хуже отсутствующего.
  Что человек видит вместо значений, не описано — **D-64**, и это одно правило на весь каталог,
  а не частный случай генератора.
