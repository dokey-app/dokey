## 0. Что считается результатом

### 0.1. Место в цепочке

```
design-system-prompt  →  tokens/*.css  →  ЭТОТ ПРОМТ  →  components/*  →  screens-prompt → макеты
                                              ↑
                                    читает токены по ИМЕНАМ,
                                    значений не знает и знать не должен
```

Библиотека — потребитель токенов, а не их второй источник. Это единственная причина, по которой
в §2 нет ни одного hex, ни одного пикселя кегля и ни одной длительности: компонент пишет
`var(--action-primary)`, а чему равен `--action-primary`, решает `tokens/colors.css`.
Вписать значение числом — дефект, а не оптимизация.

### 0.2. Компоненты — спецификация, а не код поставки

**D-54 п. 1.** React в сборку продукта не входит: стек — Astro с островами на ванильном
TypeScript, бюджет initial JS ≤ 40 KB gzip, а React с React DOM — около 45 KB. Библиотека пишется
на React с инлайновыми стилями поверх CSS-переменных **именно для того, чтобы её читали как
контракт**: пропсы, состояния, разметка, ARIA и тексты переносятся в островах один в один, а
файлы `.jsx` в продукт не копируются никогда.

Из этого — требование к выводу: **`.d.ts` важнее `.jsx`.** Контракт пропсов и описание состояний
— то, что переживёт перенос; реализация — иллюстрация к нему.

### 0.3. Токены приходят файлами

К промту прилагаются `tokens/fonts.css`, `colors.css`, `typography.css`, `spacing.css`,
`radius.css`, `elevation.css`, `motion.css`, `base.css`. Если инструмент не принимает вложения,
их содержимое вставляется в конец промта **как файлы, без пересказа значений в тексте задания**.
Обратный порядок (переписать значения словами в промт) запрещён: он создаёт второй источник
истины по цвету и кеглю.

### 0.4. Проверяемый результат

| # | Условие | Чем проверяется |
|---|---|---|
| 1 | 22 компонента в пяти папках, у каждого `.jsx`, `.d.ts`, `.prompt.md` | наличие файлов |
| 2 | У каждой папки — витрина `*.card.html`, открывается и показывает все варианты и состояния | открыть в браузере |
| 3 | Ни одного литерального значения цвета, кегля, отступа, радиуса, тени, длительности в `.jsx` | grep по `#`, `px`, `ms` вне `var(...)` |
| 4 | Каждый интерактивный компонент проходит клавиатурой без мыши и имеет видимое кольцо фокуса | обход Tab |
| 5 | Нажимаемая цель ≥ `--target-min` у всех интерактивных | замер |
| 6 | Все тексты примеров — по-русски и по правилам §5 | чтение |

## 1. Инструмент и режим генерации

**Куда вставлять.** Claude (Artifacts или проект с файлами). Витрины `*.card.html` — статические
страницы; чтобы они открывались без сборки, React, ReactDOM и Babel в них подключаются с CDN.
**Это допустимо только в витринах:** они демонстрационная оснастка и в продукт не входят никогда.
В самих компонентах сторонних ссылок нет.

**По папкам, а не всё сразу.** Пять прогонов: `core`, `forms`, `navigation`, `feedback`, `tools`.
Блок «Общий контекст» (§2, разделы 1–5) копируется в начало каждого.

## 2. Промт

```text
Ты пишешь библиотеку компонентов дизайн-системы DoKey. Токены уже существуют и приложены
файлами — ты их ПОТРЕБЛЯЕШЬ по именам переменных и не назначаешь ни одного значения сам.
Экраны продукта ты не рисуешь: это предмет отдельного задания.

======================== 1. ПРОДУКТ И АУДИТОРИЯ ========================

DoKey — набор браузерных инструментов для разработчика: JSON Workbench, JWT Inspector,
Base64 Encoder/Decoder, URL Encoder/Decoder, Unix Timestamp Converter, UUID/ULID Generator.
Всё считается в браузере: сервера, аккаунтов, синхронизации и истории операций нет. Продукт —
PWA, работает офлайн. Интерфейс русский, технические термины английские.

Пользователь — разработчик на работе, десктопный браузер, реальная рабочая ширина 700–900 px.
Руки на клавиатуре, буфер уже заполнен, операция займёт полминуты и вклинилась в отладку.
Клавиатурный путь — основной, а не запасной.

======================== 2. ЖЁСТКИЕ РАМКИ ========================

1. ЗНАЧЕНИЯ ТОЛЬКО ЧЕРЕЗ var(). Ни одного hex, ни одного px кегля, ни одного ms в компоненте.
   Отступы, радиусы, тени, длительности, цвета — все из приложенных токенов. Если нужного токена
   нет — НЕ придумывай значение: назови недостающий токен в конце ответа отдельным списком.
2. React — ЯЗЫК СПЕЦИФИКАЦИИ, а не поставки. Продукт собирается на Astro с островами на ванильном
   TypeScript; эти файлы туда не копируются. Поэтому: никаких хуков сверх useState/useRef,
   никаких контекстов, порталов, сторонних библиотек, forwardRef-цепочек и «умных» абстракций.
   Компонент должен читаться человеком, который будет переписывать его на ванильный TS.
3. Стили — ИНЛАЙНОВЫЕ объекты style поверх CSS-переменных. Ни Tailwind, ни CSS-in-JS, ни модулей,
   ни classNames. Причина та же: инлайновый стиль читается как таблица свойств.
4. НОЛЬ сторонних origin внутри компонентов. В витринах *.card.html CDN допустим (они не входят
   в продукт), в компонентах — нет.
5. Доступность — часть контракта, а не отделка. См. §4.

======================== 3. ГОЛОС И ТЕКСТ ПРИМЕРОВ ========================

Все подписи, плейсхолдеры и примеры — по-русски, обычным регистром предложения (не CAPS,
не Title Case). Технические термины по-английски без перевода и кавычек: payload, header,
signature, base64, timestamp, HS256.

Кнопка — глагол в повелительном наклонении плюс объект, когда без него действие неоднозначно;
предел 20 знаков: «Декодировать», «Скопировать», «Очистить», «Проверить подпись»,
«Продолжить с этим». У глагола «проверить» объект обязателен ВСЕГДА.
Точки в конце заголовков и подписей полей не ставим; в подсказках из двух и более
предложений — ставим.

Ошибки описывают факт и ожидание, без извинений и без вины пользователя: «Ожидались три
сегмента, разделённые точкой», «Некорректная base64-строка». Пустые состояния говорят, что
делать: «Вставьте токен — результат появится здесь».

Числа моноширинным, с неразрывным пробелом перед единицей. Единица байта — «Б», не «B».
Счётчик пишет «знаков» полностью, без «симв.»: 418 Б, 24 знака.

ЭМОДЗИ И ВОСКЛИЦАТЕЛЬНЫЕ ЗНАКИ НЕ ИСПОЛЬЗУЮТСЯ НИГДЕ, включая примеры и документацию.

======================== 4. ДОСТУПНОСТЬ — КОНТРАКТ ========================

- Клавиатура проходит всё: Tab по порядку, Enter/Space активируют, Esc закрывает
  наложенное, стрелки двигают внутри группы (radio, tabs, список палитры).
- Кольцо фокуса — var(--ring-focus), ВИДИМОЕ на обеих темах. outline: none без замены запрещён.
- Нажимаемая цель не меньше var(--target-min) по обеим осям, даже если глиф мельче.
- Цвет не бывает единственным носителем смысла: рядом со статусным цветом всегда слово или
  форма. Точка без слова — нарушение.
- У иконки без подписи обязателен aria-label; у декоративной иконки — aria-hidden.
- Ошибка поля связана с полем через aria-describedby и aria-invalid, а не только цветом рамки.
- Модальное окно: role="dialog", aria-modal, фокус входит внутрь и не покидает его, Esc
  закрывает, при закрытии фокус возвращается на вызвавший элемент.
- Состояния статуса объявляются: role="status" для нейтральных, role="alert" для ошибок.
- prefers-reduced-motion уважается — длительности обнуляются, а не «уменьшаются».

======================== 5. СОСТОЯНИЯ — ОДИНАКОВО У ВСЕХ ========================

Ховер:    нейтральные поверхности — подложка var(--surface-hover), НЕ изменение прозрачности;
          primary — var(--action-primary-hover)
Press:    var(--action-primary-active) плюс сдвиг на 0.5px вниз. Масштабирования и пружин НЕТ
Focus:    var(--ring-focus); у полей дополнительно граница var(--border-accent)
Disabled: opacity 0.45 и cursor: not-allowed; цвета НЕ меняются
Ошибка:   граница var(--border-danger) и var(--ring-danger); текст подсказки ЗАМЕНЯЕТСЯ
          сообщением, а не дополняется им
Переход:  var(--transition-control); анимируем цвет, тень, прозрачность, небольшой сдвиг.
          Размеры не анимируем

Граница — основной способ разделения, тень — вторичный. Там, где граница ОПОЗНАЁТ контрол
(поле, чекбокс, переключатель), берётся var(--border-control), а не декоративный
var(--border-default): у второго контраст ниже требуемых 3:1.

======================== 6. ЧТО ВЫВЕСТИ ========================

Двадцать два компонента в пяти папках. У КАЖДОГО три файла:
  <Name>.jsx        реализация на React с инлайновыми стилями поверх var()
  <Name>.d.ts       контракт пропсов — ГЛАВНЫЙ артефакт, переживает перенос на Astro
  <Name>.prompt.md  когда применять, один пример кода, перечень вариантов и запретов
И у каждой папки — витрина <folder>.card.html со всеми вариантами и всеми состояниями.

Button      variant: primary | secondary | ghost | soft | danger
            size: sm | md | lg (высоты --control-height-sm/md/lg)
            iconLeft, iconRight, fullWidth
            ПРАВИЛО: ровно один primary на экран. Два primary рядом — дефект

Kbd         клавиша в подсказках: Ctrl K, Esc, стрелки. Продукт управляется с клавиатуры,

======================== 7. БИБЛИОТЕКА ШИРЕ ПРОДУКТА — И ЭТО НАРОЧНО ========================

Библиотека собирается как система портала утилит ВООБЩЕ. Конкретный продукт DoKey в первой
волне применяет тринадцать компонентов из двадцати двух:

  применяются: Button, IconButton, Badge, Tag, Card, Kbd, Input, Textarea, Dialog,
               EmptyState, CodePane, CopyButton, Icon
  не применяются: ToolCard, Tabs, Breadcrumbs, Select, Checkbox, RadioGroup, Switch,
               Toast, Tooltip

Девять неприменяемых — НЕ дефект и не повод их не писать: соответствующего экрана в первой
волне просто нет (витрины каталога нет — каталог существует как поиск; настроек нет; вкладок
нет — режим переключается чипсом; иерархии нет). Пиши все двадцать два, но в <Name>.prompt.md
каждого неприменяемого поставь строку о том, что в текущей волне продукта он не используется
и почему. Без этой строки через полгода неиспользуемый ToolCard всплывёт в первом же макете
как «в системе же есть».

======================== 8. ЗАПРЕЩЕНО ========================

- Литеральные значения вместо var(): hex, кегль в px, отступ в px, радиус, тень, длительность
- Tailwind, CSS-in-JS, CSS-модули, препроцессоры, classNames, сторонние UI-библиотеки
- Загрузка чего-либо с CDN ВНУТРИ компонента (в витринах *.card.html — можно)
- outline: none без видимой замены; нажимаемая цель мельче var(--target-min)
- Точка без слова, цвет как единственный носитель смысла
- Вторая pill-форма помимо Tag; вторая гарнитура помимо sans и mono
- Градиенты, текстуры, стеклянные карточки, свечения, цветные левые полосы, заливка карточки
  целиком, анимация размеров, bounce
- Эмодзи и восклицательные знаки в любом файле
- Тихое расширение контракта: новый проп, которого нет в §6, называется отдельным списком
  в конце ответа с обоснованием, но не добавляется молча

======================== 9. ПРИЁМКА ========================

Прежде чем объявить работу законченной, покажи результат проверок:

1. Grep по .jsx на литералы: '#', 'px' и 'ms' вне var(...). Совпадений быть не должно,
   кроме толщины штриха иконки и виражей viewBox.
2. Обойди каждую витрину Tab-ом от начала до конца: каждый интерактивный элемент получает
   видимое кольцо, порядок совпадает с визуальным, ловушек нет нигде, кроме Dialog.
3. Переключи [data-theme="dark"] на витрине: ни один компонент не теряет контраст, кольцо
   фокуса видно, CodePane остаётся тёмной.
4. Перечисли компоненты, у которых пришлось додумать поведение, и что именно.
5. Перечисли токены, которых не хватило.
```

## 3. Приёмка промта

Промт принят, когда прогон даёт библиотеку, чьи `.d.ts` совпадают с текущими по составу пропсов,
а `.jsx` не содержат литеральных значений. Расхождение по `.jsx` допустимо — это иллюстрация;
расхождение по `.d.ts` разбирается: контракт переживает перенос на Astro, и разошедшийся контракт
означает разошедшуюся спецификацию.

**Отклонения продукта от библиотеки живут не здесь.** Подпись `Скопировать` вместо `Копировать`,
подтверждение 1,2 с, неиспользуемые `Badge dot` и `Card interactive`, отсутствие `Toast` как
класса сообщений — всё это [design-plan.md](design-plan.md) §5.3, и библиотека о них не знает.
