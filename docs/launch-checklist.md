## 0. Соглашения

**ЧЛ-NN** — пункт чек-листа. Пункт бинарен: он либо отмечен, либо нет. Формулировок «почти»,
«в целом», «в основном работает» в документе нет по построению — там, где источник допускал такое
чтение, пункт переписан в проверяемый факт (например, «алерты приходят» → «три существующих алерта
проверены искусственным срабатыванием, дата прогона записана»).

**Отметка — это факт с адресом:** ссылка на прогон, номер issue, дата, файл в репозитории или
строка в релизной заметке. Мнение о готовности отметкой не является (test-plan §7.1).

**Два класса пунктов.**

| Класс | Что означает | Что делаем при невыполнении |
|---|---|---|
| **Стоп-фактор** | Без него релиза нет. Пункты не суммируются и не компенсируют друг друга | Тег не ставится. Срок M-01 при этом не двигается — двигается состав (D-77 п. 1) |
| **Желательно** | Не выпускает и не отменяет релиз | Строка в релизной заметке с причиной; пункт переезжает в межрелизное окно |

**Ответственные.** `PO` — владелец продукта, решения; `ROLE-03` — мейнтейнер, ручные прогоны и
эксплуатация; `ROLE-06` — конвейер, всё выраженное числом. **Названная слабость: все три роли —
один человек** (BRD §5), то есть проверяющий и проверяемый совпадают (Q-206, Q-220). Чек-лист это
не лечит; единственная работающая замена — правило «отметка есть факт с адресом», а не суждение.

**Чем чек-лист не является.** Ни одна PM-NN, ни реакция аудитории, ни результат бенчмарка в него
не входят: проигранный замер публикуется как есть и означает ошибку в выборе рычага, а не
незрелость релиза (D-19 п. 5, test-plan §7.4).

## 7. Чего нельзя отметить на 2026-09-07

Не часть чек-листа. Перечень пунктов, у которых сегодня нет предмета отметки, — чтобы работа
по ним планировалась заранее, а не обнаруживалась на релизной неделе.

| Пункты | Что мешает | Приоритет источника |
|---|---|---|
| ЧЛ-62, ЧЛ-63 | **Q-177** — гео не подтверждено решением, площадка VPS не названа. Блокирует подключение приёмника, а не только отметку | P1 |
| ЧЛ-23 | **Q-175** — гейт egress считает origin, а не содержимое | P1 |
| ЧЛ-22 | **Q-149** — «initial JS» не определён машинно | P1 |
| ЧЛ-24 | **Q-151** — service worker не регистрируется на голом `http`, а NFR-12 обещает 100 % без оговорок | P1 |
| ЧЛ-21 | **Q-198…Q-204** — пять NFR без исполнителя, два из них названы условием релиза | P1–P2 |
| ЧЛ-58 | **Q-172** — лицензия не названа ни одним документом | P2 |
| ЧЛ-61, ЧЛ-64 | **Q-179** — оператор и контакт не названы; без них SCR-10 неполна | P2 |
| ЧЛ-66, ЧЛ-67 | **Q-153, Q-180** — сроки хранения событий и журналов не назначены; SEC-06 требует назначить до релиза | P2 |
| ЧЛ-51, ЧЛ-65 | **Q-178, Q-194** — два поля без потребителя; приёмник хранит больше, чем отправляет браузер | P2 |
| ЧЛ-19 | **Q-207** — ни один гейт не проверен на срабатывание | P2 |
| ЧЛ-31 | **Q-187** — ретенция и шифрование дампов не назначены | P3 |
| ЧЛ-03 | **Q-209** — четыре истории несут снятую блокировку Q-72 | P3 |

**Отдельно и без пункта чек-листа: Q-206 и Q-220.** Историю принимает тот, кто её сделал, а
branch protection снимается тем же аккаунтом, который её ставил. Ни один пункт выше это не
закрывает, и делать вид, что закрывает, — худший исход для документа, который читают в декабре,
когда времени нет.
