# SCR-07 · URL Encoder/Decoder

**Реестр:** [screen-map.md](../screen-map.md) §2 · **Тип:** наполнение [SCR-03](scr-03-tool-route.md) ·
**Роль:** ROLE-01 · **Сущности:** ENT-12, ENT-13
**Сценарии:** FL-02 целиком (собственного сценария не имеет — user-flows §6) · FL-04
**Истории:** US-025
**Решено:** чипсы у поля ввода (D-80); копирование описано REQ-INPUT-07 (D-74)

> Форма — SCR-03. Здесь описано **только отличие**. Собственного сценария у инструмента нет
> сознательно: он проходится по FL-02 целиком и отличается только преобразованием — отдельный
> сценарий добавил бы строки, а не смысл.

---

## 1. Зоны макета — отличие от SCR-03

| Зона | Что меняется |
|---|---|
| D, случай percent-строки | Одно значение: декодированный вид. Ничем не отличается от базовой формы |
| D, случай полного URL | **Разбор на компоненты:** схема, хост, порт, путь, query, фрагмент — парами «имя — значение», моноширинно, разделены линиями `--border-subtle` |
| D, блок query | Отдельная таблица параметров в две колонки: ключ и значение. **Повторяющиеся ключи не схлопываются** — они показываются отдельными строками, потому что именно повтор чаще всего и есть предмет разбора |
| D, у каждой строки | `Скопировать` на значении компонента и на паре целиком |
| E чипсы | `URL-кодировать` — обратное направление, срабатывает только по нажатию |

Таблица параметров — не карточка и не панель: те же волосяные линии, что везде. Пустые компоненты
(нет порта, нет фрагмента) **не показываются строкой с прочерком** — они отсутствуют. Строка
«порт: —» занимает место и ничего не сообщает.

---

## 2. Приоритет элементов

1. **Декодированное значение.** Чаще всего человек пришёл именно за ним: посмотреть, что на самом
   деле лежит в query из лога.
2. **Таблица параметров query.** Второй по частоте предмет: разложенный query отвечает на вопрос
   быстрее, чем декодированная строка целиком.
3. **Повторяющиеся ключи.** Единственное место экрана, где решение вёрстки меняет ответ: схлопнутый
   дубль — потерянный факт.
4. **Компоненты URL.** Схема и хост читаются глазами и без разбора; ценность разбора начинается с
   пути и query.
5. **Чипс `URL-кодировать`.** Обратное направление для того, кто вставил не то, что думал.

---

## 3. Поведение на мобильном

- **Таблица параметров становится списком пар** «ключ над значением»: две колонки на 360 px
  ломают значение, а значение здесь и есть предмет.
- **Длинные значения переносятся по символам**, а не прокручиваются горизонтально: горизонтальная
  прокрутка внутри строки прячет хвост, а хвост в percent-строке чаще всего и есть интересное.
- **Компоненты URL** остаются вертикальным списком и на десктопе, и на мобильном — перестраивать
  нечего.
- `Скопировать` у каждой строки — цель не менее 32 px; при нехватке ширины действие остаётся, а
  подпись сокращается до иконки **только здесь и только для повторяющегося действия в списке**.
  Это исключение из правила «иконка не появляется там, где помещается слово» и его надо утвердить
  вместе с D-80, а не принять молча.

## 4. Тексты

| Место | Строка |
|---|---|
| H1 | `URL Encoder/Decoder` |
| Подсказка поля | `Вставьте URL — результат появится ниже` |
| Чипс кодирования | `URL-кодировать` |
| Кнопка результата | `Скопировать` → `Скопировано` на 1,2 с |
| Ошибка разбора | `Некорректный URL: нет схемы. Добавьте https:// в начало` |
| Оборванная последовательность | Ошибка с позицией; ввод не очищается (NFR-15) |

Подписи компонентов — `схема`, `хост`, `порт`, `путь`, `query`, `фрагмент`. Слово `query` не
переводится (глоссарий §5, браузерные механизмы и термины формата), слово `заголовок` здесь не
употребляется ни в каком смысле — оно занято H1 и `title`.

**Запрещено здесь.** `Раскодировать` вместо `Декодировать` · `Расшифровать` · `Параметры запроса`
как подпись — «запрос» тянет за собой адресата, которого нет (ENT-12: у ввода адресата не
существует) · `Ошибка`, `Упс` в сообщении.

---

## 5. Состояния

- **Loading.** Не бывает: преобразование укладывается в кадр при любом реальном URL.
- **Empty.** `Пример` разобранного URL с несколькими параметрами, включая повторяющийся ключ —
  пример обязан показывать то свойство, ради которого инструмент отличается от `decodeURIComponent`
  в консоли. Таблицы параметров до первого ввода нет: не пустая таблица с заголовками, а её
  отсутствие.
- **Error.** Сообщение на месте результата, ввод не очищается, акцентная подложка на позиции оборванной
  percent-последовательности в самом поле ввода.
