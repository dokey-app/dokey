# DoKey — правила работы в репозитории

Читается в начале каждой сессии. Здесь только то, что нужно **каждый раз**; остальное — по
ссылкам в §9. Числа и обоснования живут в `docs/`, этот файл их не переопределяет.

## 1. О продукте

DoKey — каталог браузерных инструментов для разработчика (JSON, JWT, Base64, URL, timestamp,
UUID/ULID), в котором ввод физически не покидает вкладку: серверной обработки, аккаунтов, истории
и хранения нет по построению. Пользователь — инженер (backend, frontend, QA, DevOps,
интеграционный аналитик), у которого посреди другой работы возникла тридцатисекундная операция над
токеном, конфигом или ответом API. Стадия: продуктового кода ещё нет — в репозитории только
`docs/`; идёт этап **Э-0 «труба»** (T-001…T-032 из 207 задач), релиз `v1.0.0` — 2026-12-21.

## 3. Структура репозитория

Каталоги повторяют компоненты architecture §2.1 один в один: вопрос «где это живёт» не должен
требовать чтения кода.

```
dokey/
├─ .github/workflows/{pr,release,rebuild,synthetic}.yml, ISSUE_TEMPLATE/, pull_request_template.md
├─ docs/                    # корпус документов, §9
├─ infra/
│  ├─ headers/_headers      # CSP, HSTS, кеш — единственный источник заголовков
│  ├─ docker/{Dockerfile, nginx.conf}    # те же заголовки; две копии сверяет check:prod (RUN-16)
│  └─ vps/docker-compose.umami.yml
├─ scripts/gates/           # G-03…G-14, по файлу на гейт; рядом subset-fonts.ts, build-sprite.ts, bench-ttr.ts
├─ src/
│  ├─ registry/             # КМП-13: tools.ts, schema.ts (Zod), thresholds.ts, ladder.ts — источник маршрутов
│  ├─ shell/                # КМП-01: шапка, статус сети, role=status/alert, «недавние»
│  ├─ router/               # КМП-02, КМП-05: router.ts, teardown.ts, handoff.ts
│  ├─ detect/               # КМП-03: ступени лестницы и предикаты meaningfulWhen
│  ├─ palette/ egress/ analytics/        # КМП-04 · КМП-06 · КМП-07 (закрытый список полей)
│  ├─ tools/<toolId>/       # КМП-08: contract.ts, logic.ts, ui.ts — по каталогу на инструмент
│  ├─ worker/ virtual/ editor/           # КМП-09 · КМП-10 · КМП-11 (редактор — только JSON Workbench)
│  ├─ sw/ pages/ content/ ui/ styles/    # КМП-12 · КМП-14 · тексты · единая форма результата · токены
├─ fixtures/                # КМП-15: корпус фикстур (ENT-21) и генератор синтетических токенов
└─ tests/{unit, integration, e2e, invariants}/
```

## 4. Соглашения

- **Имена сущностей — строго английские из глоссария** (§5): тип, модуль, маршрут и ключ реестра
  называются колонкой «в коде»; интерфейс и документы — русской колонкой. Синоним из списка
  glossary §6 — дефект текста, а не стилистический выбор.
- **Технические термины не переводятся:** JSON, JWT, Base64, payload, service worker, timestamp,
  SBOM, provenance.
- **Файлы** — lowercase-kebab (`teardown.ts`, `build-sprite.ts`); Astro-страницы и layout —
  PascalCase (`Base.astro`). Типы — PascalCase именем из глоссария (`Tool`, `ToolContract`).
- **`Tool.id`** — ASCII kebab-case, совпадает с сегментом RU-маршрута, после релиза не меняется
  никогда. Запись в `src/registry/tools.ts` добавляется **последней** задачей среза.
- **Стили** — нативный CSS с токенами дизайн-системы; второго источника значений нет.
- **Ветка** — одна на задачу: `t-042-json-tree`. **Коммит** — один на задачу, заголовок
  `T-042: дерево JSON (US-020)`. PR обязателен даже для соло-коммита: гейты живут на PR, прямой
  пуш в `main` закрыт. Тег `vX.Y.Z` — это релиз, а не отметка.
- **Тесты.** Unit (Vitest, node) — всё, где нет сети, DOM и времени; корпус фикстур прогоняется
  целиком, падение одной фикстуры останавливает сборку. Integration — Vitest browser mode, не
  jsdom: граница с платформой (`Worker`, `crypto.subtle`, `caches`, `performance`). E2E
  (Playwright) — один тест = один FL-NN, ветви A1/A2 отдельными тестами того же файла, утверждения
  цитируют Then критериев истории. **Список маршрутов ни в одном тесте не пишется руками — он
  берётся из реестра.** Правишь лестницу — фикстуры в том же PR.

## 6. Что запрещено

Инварианты architecture §10 и запреты стека. У одиннадцати из двенадцати инвариантов есть машина,
ловящая нарушение; двенадцатый (ИНВ-12) держится обзором.

| Запрет | Почему | Чем ловится |
|---|---|---|
| Не отправлять ввод и результат за пределы вкладки; `script-src` и `connect-src` — `'self'` без исключений | Граница доверия совпадает с границей вкладки — другой защиты у продукта нет | ИНВ-01, `gate:egress` |
| Не подключать CDN, Google Fonts, unpkg, jsDelivr, Sentry, любой SDK телеметрии | Сторонних origin в релизе ровно 0, и это число показано пользователю на первом экране | ИНВ-01, `gate:egress` |
| Не писать ввод в `localStorage`, `sessionStorage`, URL, query, фрагмент, историю | Персистентность равна нулю; «сохраним черновик» ломает обещание NFR-10 | ИНВ-02, `gate:persist` |
| Не переносить состояние через границу маршрута: только **одно** значение через буфер, обнуляемый чтением; из инструмента с `sensitiveInput` — ничего | Иначе токен переживает уход с маршрута и teardown теряет смысл | ИНВ-03, ИНВ-04, RUN-02 |
| Не добавлять поля аналитики; расширение идёт публикация → список → код | Наружу уходят ровно семь полей закрытого списка (ENT-29) | ИНВ-05, `gate:fields` |
| Не заводить маршрут файлом мимо `src/registry` | Реестр — единственный источник маршрутов, sitemap, палитры и активных ступеней лестницы | ИНВ-06, `gate:sitemap`, `gate:ladder` |
| `src/registry` не импортирует `src/shell` и `src/tools` | Иначе ИНВ-06 перестаёт быть проверяемым, а критерий «diff PR не содержит файлов оболочки» — формальность | ревью PR |
| Не переименовывать `Tool.id` после релиза | Ломает сравнение метрик с прошлым релизом и сохранённые пользователем ярлыки | ИНВ-07, `gate:toolids` |
| Не рендерить лендинг и поле ввода клиентом; молчаливого отказа не бывает | Читаемо **до** выполнения JS; у четырёх состояний — четыре разных текста | ИНВ-08, RUN-13, `gate:a11y` |
| Не блокировать главный поток дольше 50 мс: разбор, форматирование, кодирование, хэширование — в Worker | «Обычно ввод маленький» — не аргумент при объявленных порогах | ИНВ-09, `gate:lh`, INP p75 |
| `skipWaiting` — только по действию человека | Обновление под работающей вкладкой стирает введённое | ИНВ-10, e2e обновления |
| В профиле `selfhosted` аналитики нет физически; образ не обращается в сеть в рантайме | «Выключить аналитику в настройках» — операция, которой не должно существовать | ИНВ-11, `test:image` |
| Не подделывать возможность браузерного API: `Math.random` вместо `getRandomValues`, «Скопировано» без копирования, своя криптография ради `http` | Единственный инвариант без полного машинного гейта — цена ошибки максимальная | ревью PR, сценарии |
| Не добавлять React, Preact, Svelte, Vue, Tailwind, headless-библиотеки, Lucide бандлом | Initial JS ≤ 40 KB gzip: React + React DOM ≈ 45 KB — нарушение до первой строки продукта | О-04, D-50 п. 5, `gate:size` |
| Не добавлять сервер приложения, БД продукта, очередь, кеш-слой, аутентификацию, шеринг | Красные линии D-05: этого нет не «пока», а как класса | ADR-12, ADR-13 |
| Не ставить зависимость, соответствие которой бюджету нечем проверить машиной; не писать `^` в манифесте | Гейт приходит вместе с инструментом, иначе выбор не проверяется, а декларируется | О-13, `gate:size` |
| Не принимать архитектурное решение внутри задачи | Решение посреди задачи не проходит ни через чей обзор и всплывает через месяц как «почему так» | tasks §0.2 |

## 7. Контур работы с `docs/tasks.md`

**Одна сессия = одна задача.**

1. Взять **верхнюю** незакрытую `- [ ]`. Стоит `⚠ Q-NN` — задача не берётся, пока вопрос открыт;
   стоит `блок: T-NNN` — сначала та задача.
2. Написать план. Не помещается на экран, трогает больше 5–7 файлов или требует решения, которого
   нет ни в decisions, ни в tasks, — задача режется, а решение выносится в `open-questions.md`.
3. Выполнить **внутри границ задачи** (графа «границы»): всё, что за ними, — предмет другой задачи.
4. Прогнать команду из графы «готово» — именно её, а не похожую. «Посмотрел глазами» готовым не
   является нигде, кроме пунктов ручного чек-листа RUN-17.
5. Отметить `- [x]`, закоммитить одним коммитом `T-NNN: что сделано (US-NNN)` в ветке `t-nnn-…`,
   открыть PR. Задача закрыта, когда команда «готово» зелёная **в CI**, а не только локально;
   чекбокс истории в `backlog.md` двигается, когда закрыты все её задачи, — не раньше.
6. **Найденное попутно не чинить.** Дефект или недоделка — новая строка `- [ ]` в конце своего
   этапа `tasks.md` по форме §0.1 (действие · US-NNN/TECH-NN · границы · готово); нехватка
   решения — строка `| Q-NNN | формулировка | источник | P1…P3 |` в `open-questions.md`. Правка не
   по теме задачи в диффе — дефект PR, а не бонус.

## 8. Перед коммитом

1. `pnpm lint && pnpm format:check && pnpm typecheck`.
2. `pnpm test:unit && pnpm test:int && pnpm test:e2e` — затронутые уровни целиком, не отдельный тест.
3. Команда из графы «готово» задачи плюс гейты, чей предмет затронут (при сомнении — `pnpm gates`).
4. Дифф не выходит за границы задачи; файлов не больше 5–7; коммит один.
5. Тексты интерфейса — дословно из content-guide и glossary §4; синонимов из glossary §6 нет.
6. Новых полей аналитики нет; новых зависимостей нет — а если есть, версия точная и гейт назван.
7. Трогали лестницу — фикстуры в том же PR; трогали контракт инструмента — пункт ENT-25 обновлён.
8. Заголовок коммита содержит `T-NNN` и `US-NNN`; отметка `- [x]` в `tasks.md` — в том же коммите.
