## Approach

`.size-limit.json` — единственный источник бюджетов; строка NFR-03 получает `"measure": "initial-js"`
и `"path": "dist/**/*.html"` — корни графа, а не файлы счёта. `size.ts` по каждому HTML:

1. `<script>` исполняемого типа (без `type`, JS MIME, `module`); JSON-LD, `importmap` — не JS;
2. инлайновые — слагаемое 1 (каждое во временный файл, чтобы считал тот же size-limit);
3. `<script src>` и статические `import`/`export … from` инлайновых модулей — корни слагаемого 2;
   обход по статическим импортам, `import(` не совпадает по построению регулярки;
4. спецификатор `/…` — от корня `dist`, `./` `../` — от файла; иное (URL, голое имя, файла нет) —
   `fail` с именем маршрута: неразрешённое не может молча выпасть из счёта;
5. порог — к максимуму по маршрутам; вывод называет маршрут-максимум и все превысившие.

Остальные три строки — глоб без `measure`, имя пути — договор со своей задачей:
чанк редактора `dist/_astro/editor.*.js` (90 kB, T-052/T-193), шрифты Mono 400/600
`dist/fonts/jetbrains-mono-*.woff2` (48 kB, T-028), чанки каталога `dist/_astro/tool-*.js`
(120 kB — «сумма чанков каталога без редактора» D-78, T-052/T-144). Пока предмета нет — «предмета нет».

Отвергнуто: `es-module-lexer` — новая зависимость требует строки tech-stack §3 (D-154), это за
границами (позже отменено **D-158**: регулярка давала ложный провал на тексте в форме импорта
внутри комментариев и строк, лексер стал прямой devDependency со строкой tech-stack §3) · `build.manifest` Vite — метаданные сборки, а не артефакт (D-88), и `astro.config.mjs` ·
gzip инлайна через `zlib` — второй счётчик рядом с size-limit (ADR-16) · прогон в браузере — D-88.
