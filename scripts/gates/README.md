# Гейты G-01…G-14

Четырнадцать адресов заведены в Э-0 целиком; исполняются те, у кого уже есть предмет
(implementation-plan §2.2). Гейт без предмета печатает `ПУСТО` и этап включения — иначе
через месяц «зелёный, потому что проверено» не отличается от «зелёного, потому что пусто».

Сверх четырнадцати: `headers-parity.ts` (`pnpm gate:headers-parity`) сверяет две копии
заголовков ответа — `infra/headers/_headers` и `infra/docker/nginx.conf`. Копии существуют
по устройству поставки; **D-107** делает источник одним — обе выводятся из `infra/headers/policy.ts`, а прогон сверяет, что перегенерация не даёт диффа.

## Как добавить предмет гейту

Гейт заменяет `run: () => pending('Э-N')` на настоящую проверку и меняет `enabledIn` на этап,
в котором это произошло. В том же PR заводится негативная проверка в `tests/gates/negative/`:
**гейт, ни разу не падавший, не считается заведённым** (Q-207, NFR-17).
