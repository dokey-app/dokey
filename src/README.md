# Дерево `src` — по компоненту на каталог

Каталоги повторяют компоненты [architecture §2.1](../docs/architecture.md) один в один, чтобы
вопрос «где это живёт» не требовал чтения кода, а PR по контракту D-21 падал в очевидное место.
Каталог без строки в этой таблице — дефект PR, а не новый компонент.

## Три правила, которые дороже состава дерева

1. **`registry` не импортирует ничего из `shell` и `tools`.** Иначе ИНВ-06 перестаёт быть
   проверяемым, а критерий US-002 «дифф PR не содержит файлов оболочки» становится
   формальностью.
2. **`tools/<toolId>` — единственное место, куда добавляется позиция каталога.** Всё остальное
   производно от реестра, и это проверяют гейты G-07 и G-08, а не ревью.
3. **Маршрут не заводится мимо `registry`** (ИНВ-06). Страница в `pages/`, которой нет в
   реестре, не попадает ни в sitemap, ни в палитру — и это ловится гейтом, а не глазами.

Пустые каталоги держатся `.gitkeep` до задачи, которая их наполняет: место компонента
объявлено раньше, чем в нём появляется код, — так порядок задач читается из дерева.
