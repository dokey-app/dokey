# Библиотека промптов: одноразовые задачи

Делаются раз на проект — им не нужны постоянные команды.
Скопируйте, поправьте, вставьте в Claude Code.

---

## Докеризация

    Задокеризируй проект по docs/architecture.md: multi-stage
    Dockerfile на каждое приложение (минимальный образ, non-root
    user, слои с кешированием зависимостей), docker-compose.yml для
    локальной разработки с БД и healthcheck'ами.

    Проверка: docker compose up должен пройти healthcheck'и всех
    сервисов; docker compose down -v && up — повториться с нуля.
    Покажи вывод. Размер финальных образов — в отчёт.

---

## CI (GitHub Actions)

    Настрой CI в .github/workflows/ci.yml: на PR — lint, typecheck,
    тесты, сборка (с кешем зависимостей); джобы параллельно, где
    возможно. Добавь джобу contracts: регенерируй
    docs/openapi.yaml из api-spec.md и упади, если diff не
    пустой (yaml редактируют только генерацией). Бейдж — в README.

    Проверка: прогони джобы локально через act (или объясни, какие
    шаги не воспроизводимы локально и почему), покажи результат.
    Пайплайн должен падать при падающем тесте — докажи намеренно
    сломанным тестом, затем убери его.

---

## Автоматизация сборки (Makefile / just)

    Создай Makefile с целями: dev, build, test, test-fast, lint,
    typecheck, clean, db-migrate, db-reset, openapi (регенерация
    docs/openapi.yaml из api-spec.md). Каждая цель — одна
    команда из CLAUDE.md, никакой логики в make. Цель help
    (по умолчанию) печатает описание всех целей.

    Проверка: запусти каждую цель, покажи вывод. Обнови CLAUDE.md:
    замени прямые команды на make-цели, если так короче.

---

## Проверка инвариантов документации (разово или в CI)

    Напиши scripts/check-invariants.sh, который печатает
    нарушения и ничего не чинит:
    - имена сущностей в коде (модели, таблицы) ≠ английским именам
      ENT-NN из docs/glossary.md
    - эндпоинты в коде ≠ docs/api-spec.md
    - события аналитики в коде ≠ EVT-NN из docs/analytics-spec.md
    - US отмечена [x] в backlog.md, а её T-NNN в tasks.md — нет
    Exit 1 при любом нарушении. Подключи в CI как джобу docs.

## Автоматизация без человека (headless)

Когда цикл обкатан вручную, части конвейера снимаются с вас:

**Авторевью каждого PR** — Claude Code GitHub Action (см.
официальную документацию): ревью дифа против плана из
docs/plans/ и линкованной US прямо в PR, до человеческого ревью.

**Ночная синхронизация документации:**

    # .github/workflows/docs-sync.yml (по расписанию)
    claude -p "/docs" --permission-mode auto \
      --allowedTools "Read,Edit,Bash(git *)"
    # затем джоба открывает PR с изменениями docs/

**Прогон очереди пачкой** (осторожно, сначала 1–2 задачи):

    # каждая T-NNN -> отдельный worktree и PR
    claude -p "/plan" && claude -p "/build" && claude -p "/ship"

Условие для пачки: в open-questions.md нет открытых P1/P2 —
иначе /plan остановится на первой же задаче с вопросом.

**Stop-гейт (жёсткий режим)** — не давать Claude завершать ход
при падающих тестах. В settings.json:

    "Stop": [{ "hooks": [{ "type": "command",
      "command": "sh scripts/stop-gate.sh" }] }]

scripts/stop-gate.sh уже в ките: подставьте свою быструю
тестовую цель. Включайте только на стабильном проекте — на раннем
этапе гейт мешает итерировать.
