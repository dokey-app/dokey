# Зона `dokey.ru` (T-001, TECH-01)

Задача T-001 выполняется человеком с доступом к регистратору — здесь записано, что именно
должно получиться, чтобы результат можно было проверить, а не принять на слово.

## Что должно быть

1. Домен `dokey.ru` зарегистрирован, зона делегирована на Cloudflare.
2. Записи `dokey.ru` и `www.dokey.ru` указывают на Workers-проект `dokey` (см.
   [wrangler.toml](../../wrangler.toml)). Custom Domain `dokey.ru` привязывает ROLE-03 один раз в
   панели Cloudflare до первого тега, а `wrangler.toml` повторяет привязку: у токена деплоя нет
   права на маршруты (**D-179**).
3. TLS выдан и действует; `www` отвечает редиректом на apex.
4. HSTS отдаётся с продакшн-ответом: `max-age=63072000; includeSubDomains; preload`
   — значение живёт в [infra/headers/\_headers](../headers/_headers), а не в панели провайдера
   (ST-03).
5. Почтовый алиас `privacy@dokey.ru` заведён и принимает письмо — это контакт субъекта данных
   на SCR-10 (**D-125** п. 2). Адрес пересылки наружу не публикуется: меняется ящик, а не
   страница.
6. «Managed robots.txt» Cloudflare в зоне **выключен** (**D-164** п. 4): источник `robots.txt` —
   репозиторий, файл выводится на сборке из того же признака индексации, что `noindex`.
7. «Network Error Logging» Cloudflare в зоне **выключен** (**D-180**): иначе край дописывает к
   каждому ответу `Report-To` и `NEL`, и браузер посетителя шлёт отчёты на
   `a.nel.cloudflare.com` — сторонний origin по ИНВ-01. Панель зоны или
   `PATCH /zones/{zone_id}/settings/nel` со значением `off`.

Зона `.ru` в HSTS preload **не входит**: HTTP закрывают редирект Cloudflare «Always Use HTTPS»,
заголовок HSTS из `_headers` и подача самого домена в hstspreload.org — задача T-223 (D-175).
До включения домена в списки браузеров первый заход по `http://` возможен и обрывается редиректом.

## Учётные записи

Регистратор — **отдельная учётная запись от Cloudflare**: ROLE-03 называет четыре, и регистратор
домена среди них (ИНТ-09). Аккаунт Cloudflare заводится **раньше** регистрации домена — зона
делегируется на него же (**D-86** п. 3).

- **Второй фактор обязателен в обеих** — TOTP или passkey; SMS не используется (SEC-11).
  Резервные коды хранятся офлайн, не на том же устройстве.
- **Регистратор — не Cloudflare** (**D-162** п. 4): при потере аккаунта Cloudflare NS меняются у
  регистратора и включается план ST-03. **Домен продлевается по году** (**D-177**).
- **На регистраторе включены registrar lock и автопродление**, напоминание об истечении стоит
  за 60 дней (SEC-12). Домен — единственный отказ, у которого нет обходного пути внутри
  архитектуры (ИНТ-09).
- **Набор восстановления — резервные коды и ключи — хранится офлайн**, и к нему заведён
  отложенный аварийный доступ доверенного лица: аварийный доступ менеджера паролей с задержкой
  или запечатанный конверт (**D-162** п. 5). Второго владельца с постоянными правами нет. Кто это
  лицо и где лежит набор, в репозитории не записывается; порядок — рунбук доступа
  `infra/access/README.md` (T-215).

## Как проверить

Проверки разведены по задачам решением **D-114**: делегирование проверяется делегированием,
заголовки — первым деплоем. До T-011 записи на apex нет, имя не резолвится, и ответа хостинга
не существует — включать HSTS в панели провайдера ради формы приёмки нельзя (п. 4 выше).

**T-001 — зона делегирована, TLS выдан, алиас принимает письмо:**

```bash
dig NS dokey.ru +short          # два NS Cloudflare
dig MX dokey.ru +short          # route{1,2,3}.mx.cloudflare.net — Email Routing
curl -s "https://api.certspotter.com/v1/issuances?domain=dokey.ru&expand=dns_names" \
  | grep -c dokey.ru            # ≥ 1 сертификат в логах Certificate Transparency
```

На Windows без `dig` то же самое даёт `Resolve-DnsName -Type NS dokey.ru -Server 1.1.1.1`.
Сертификат проверяется по CT-логу, а не `curl`: до T-011 проксируемой записи нет и предъявлять
его некому. `crt.sh` для той же проверки годится, но отвечал 404 и 502 в день приёмки T-001.

Письмо, отправленное на `privacy@dokey.ru`, доходит до ящика пересылки.

**T-011 — прод отвечает и отдаёт заголовки из `_headers`:**

```bash
curl -sI https://dokey.ru | head -1
curl -sI https://dokey.ru | grep -i 'strict-transport-security'
```

Полную сверку заголовков делает `pnpm check:headers` с `DOKEY_TARGET=https://dokey.ru`.

**T-235 — отчётов NEL на ответах нет (D-180):**

```bash
curl -sI https://dokey.ru | grep -ciE '^(nel|report-to|reporting-endpoints):'   # 0
```
