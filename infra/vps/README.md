# Приёмник аналитики (T-026, TECH-03)

Umami 3.3.1 и PostgreSQL 18.6 на собственном VPS. Приёмник поднимается **до первой строки
продуктового кода** (D-76 п. 4): без него у гейта G-05 и всего EP-09 нет предмета.

## Почему свой VPS, а не облачная панель

Обещание продукта — «ввод не покидает вкладку» — держится строкой `connect-src 'self'`.
Любой чужой origin у счётчика сломал бы его об собственную вёрстку. Поэтому события идут
на свой origin через прокси `/s/*` (КМП-18, ADR-11, D-22), а приёмник наружу не смотрит.

## Поднять

```bash
export POSTGRES_PASSWORD=...      # из менеджера секретов, не из истории shell
export APP_SECRET=...
docker compose -f docker-compose.umami.yml up -d
docker compose -f docker-compose.umami.yml ps
```

Панель — на `127.0.0.1:3000`, снаружи недоступна. Доступ мейнтейнера — через SSH-туннель:

```bash
ssh -N -L 3000:127.0.0.1:3000 <vps>
```

## Дамп

Дамп шифруется **до записи на носитель** (**D-169**): открытый ключ `age` лежит в репозитории —
`infra/vps/dump-recipient.txt`, закрытый хранится офлайн у мейнтейнера и на VPS не попадает.
Незашифрованный дамп на диск не пишется.

```bash
docker compose -f docker-compose.umami.yml exec -T db \
  pg_dump -U umami -d umami --format=custom \
  | age -r "$(cat dump-recipient.txt)" > umami-$(date +%F).dump.age
```

Снятие дампа одной командой — форма приёмки T-026. Команда, как и остальные здесь, запускается
из `infra/vps/`.

Дамп на носителе читается только закрытым ключом, то есть у мейнтейнера, а не на VPS:

```bash
age -d -i <закрытый-ключ> umami-YYYY-MM-DD.dump.age | pg_restore --list > /dev/null
```

Той же расшифровкой начинается репетиция восстановления — она заодно доказывает, что закрытый
ключ цел (D-169 п. 5).

## Ежемесячный прогон

Одно задание в фиксированном порядке (**D-169** п. 3, срок — **D-113** п. 1):

1. удалить записи событий старше 12 месяцев;
2. снять зашифрованный дамп командой выше, проверив поток `pg_restore --list` до шифрования
   (закрытого ключа на VPS нет — расшифровку проверяет репетиция ЧЛ-30);
3. удалить предыдущий дамп.

На VPS — не больше одного регулярного дампа и одного дампа перед миграцией Umami; дамп перед
миграцией удаляется ближайшим прогоном. Копии вне VPS нет: в копии запись живёт не дольше, чем в
базе, а потеря истории аналитики при гибели VPS принята (ИНТ-03, NFR-11). Сам скрипт
`infra/vps/monthly.sh` и файл `dump-recipient.txt` появляются с задачей **T-216**.
